# CrowdStrike AWS Onboarding Guide

## Overview
This guide walks through deploying CrowdStrike Falcon Cloud Security (CSPM) into an AWS account using customized CloudFormation templates. The templates have been modified to use a least-privilege IAM reader role instead of CrowdStrike's default broad `SecurityAudit` policy.

---

## Prerequisites

- AWS account access with permissions to create IAM roles, S3 buckets, and CloudFormation stacks
- CrowdStrike Falcon API credentials (Client ID and Client Secret) with CSPM registration permissions
- AWS CLI installed and configured (for S3 upload steps)

---

## Step 1 — Create an S3 Bucket

Create an S3 bucket in the **same AWS region** you will deploy the CloudFormation stack into. CloudFormation requires nested template URLs to be in the same region as the stack.

```bash
aws s3api create-bucket \
  --bucket <your-bucket-name> \
  --region us-east-1
```

> **Note:** For regions other than `us-east-1`, add `--create-bucket-configuration LocationConstraint=<region>`.

Verify the bucket region:

```bash
aws s3api get-bucket-location --bucket <your-bucket-name>
```

A `null` response means `us-east-1`. Any other value is the region name.

---

## Step 2 — Update the Root Template

In `cs_aws_root.yaml`, find the two `TemplateURL` references for the asset inventory nested stack (one for single-account, one for StackSet) and replace them with your bucket URL:

```yaml
TemplateURL: https://<your-bucket-name>.s3.amazonaws.com/cs_aws_asset_inventory-1.3.yaml
```

There are two occurrences — both must be updated.

---

## Step 3 — Upload Templates to S3

Upload both template files to your bucket:

```bash
aws s3 cp cs_aws_asset_inventory-1.3.yaml s3://<your-bucket-name>/cs_aws_asset_inventory-1.3.yaml
aws s3 cp cs_aws_root.yaml s3://<your-bucket-name>/cs_aws_root.yaml
```

---

## Step 4 — Generate the Launch URL from the Falcon Console

The deployment URL is generated by the CrowdStrike Falcon console and contains pre-populated parameters specific to your Falcon account (API credentials, external ID, CrowdStrike role ARN, etc.).

1. In the Falcon console, go to **Cloud Security** > **AWS Registration** and proceed through the onboarding workflow until you reach the CloudFormation launch step
2. Copy the generated launch URL — do **not** click it yet. It will look like this:

```
https://console.aws.amazon.com/cloudformation/home?region=us-east-1#/stacks/create/review?templateURL=https://cs-prod-cloudconnect-templates-use1-4721cdb0.s3.amazonaws.com/modular/cs_aws_root.yaml&stackName=CrowdStrike-Integration&param_EnableAssetInventory=true&param_Enable1ClickSensorManagement=false&param_EnableRealtimeVisibilityAndDetection=false&param_OrganizationID=&param_ProvisionOU=&param_DelegatedAdmin=false&param_UseExistingIAMReaderRole=false&param_FalconClientID=<your-falcon-client-id>&param_FalconClientSecret=<your-falcon-client-secret>&param_RoleName=<your-role-name>&param_CSRoleArn=<crowdstrike-role-arn>&param_ExternalID=<your-external-id>
```

3. In the URL, find the `templateURL=` parameter and replace the CrowdStrike-hosted S3 URL with your bucket URL:

**Before:**
```
templateURL=https://cs-prod-cloudconnect-templates-use1-4721cdb0.s3.amazonaws.com/modular/cs_aws_root.yaml
```

**After:**
```
templateURL=https://<your-bucket-name>.s3.amazonaws.com/cs_aws_root.yaml
```

4. Open the modified URL in your browser — it will pre-fill the stack name and all Falcon-specific parameters
5. Review the parameters and click **Create stack**

## Template Files

| File | Description |
|---|---|
| `cs_aws_root.yaml` | Root template — orchestrates all CrowdStrike features |
| `cs_aws_asset_inventory-1.3.yaml` | Nested template — provisions the CSPM reader IAM role |

### Changes from CrowdStrike Defaults

**`cs_aws_root.yaml`**
- `TemplateURL` for asset inventory nested stack updated to point to your S3 bucket
- `Default: 'CrowdStrikeCSPMReaderRole'` added to the `RoleName` parameter

**`cs_aws_asset_inventory-1.3.yaml`**
- Removed the `SecurityAudit` AWS managed policy
- Removed the original ~140-action `cspm_config` inline policy
- Replaced with a focused inline policy (`cspm_sensor_coverage`) — see below

---

## IAM Reader Role

**Role name:** `CrowdStrikeCSPMReaderRole` (default, can be overridden at deploy time)

**Trust policy:** CrowdStrike's IAM role (provided by the Falcon console as `CSRoleArn`) can assume this role, gated by an `sts:ExternalId` condition.

**Inline policy `cspm_sensor_coverage`:**

| Service | Permissions | Purpose |
|---|---|---|
| CloudFormation | `DescribeStacks`, `DescribeStackResources`, `DescribeStackSet` | Stack validation |
| EC2 | `Describe*`, `GetEbsDefaultKmsKeyId`, `GetEbsEncryptionByDefault` | Instance inventory + encryption posture |
| IAM | `GenerateCredentialReport`, `GenerateServiceLastAccessedDetails`, `Get*`, `List*`, `SimulateCustomPolicy`, `SimulatePrincipalPolicy` | Identity posture |
| Organizations | `Describe*`, `List*` | Org structure visibility |
| EventBridge | `Describe*`, `List*` | Event rule visibility |

All actions scoped to `Resource: *`.
